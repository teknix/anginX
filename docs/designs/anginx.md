# CEO Plan: anginX — Dynamic Nginx Registration Proxy
Generated by /plan-ceo-review on 2026-05-22
Branch: unknown | Mode: SCOPE EXPANSION
Repo: local (no remote yet)

## Vision

anginX is a zero-ops service mesh for Docker-based microservices. A Flask app
imports `anginx_client`, calls `anginx.register()` at startup, and is live on
`sub.domain.com` with SSL — no nginx config files touched by human hands, ever.
When the app stops cleanly, it deregisters; when it restarts, it re-registers
(idempotent — no deregister-first needed). Config changes propagate via graceful
nginx reload (SIGHUP, async, after nginx -t passes). The dashboard shows every
service, every domain, and last-seen timestamps.

Note: Heartbeat/auto-deregistration is the north-star for v1+; v1 ships explicit
deregistration only. See TODOS.md.

## Deployment Architecture

Single Docker image running **nginx + Python API (Flask/Gunicorn --workers=1)
via supervisord**.

- nginx listens on ports 80 (HTTP→HTTPS redirect) and 443 (SSL)
- Flask API (Gunicorn --workers=1) runs on 127.0.0.1:5000 internally
- nginx proxies API routes to Flask; both processes in same container
- Both supervisord children run as **root** (Flask must send SIGHUP to nginx master)
- Gunicorn chosen over Flask dev server: handles socket timeouts and hung connections
  correctly; `--workers=1` preserves single-threaded behavior (no concurrent reload races)

**Startup ordering:** supervisord runs nginx directly. Gunicorn is launched via a
wrapper script (`entrypoint/start-gunicorn.sh`) that polls `/run/nginx.pid` (0.5s
interval, 10s max, then exits with error) before exec'ing gunicorn. supervisord's
`[program:gunicorn]` entry points to the wrapper script, not gunicorn directly.
This prevents Flask accepting registrations before nginx master is running and able
to process `nginx -s reload`.

**Startup state rebuild:** Flask scans `conf.d/`, parses `# anginx:` headers (skipping
`_ssl_*` prefixed files), and rebuilds the in-memory registry dict. No `nginx -t`
pass over existing confs — nginx itself refuses to start with an invalid config, and
the GET /health check catches that. Startup time is flat regardless of service count.

**Docker network requirement:** Upstream containers must share a Docker network with
anginX (e.g., `app_network`). Container names = Docker DNS hostnames. Include example
in docker-compose.yml.

```
Docker container: anginX
┌──────────────────────────────────────────────────────────┐
│  supervisord                                              │
│  ├── nginx (ports 80, 443)  [root]                       │
│  │     ├── /new/<key>  → proxy 127.0.0.1:5000           │
│  │     ├── /services   → proxy 127.0.0.1:5000           │
│  │     ├── /dashboard  → proxy 127.0.0.1:5000           │
│  │     ├── /health     → proxy 127.0.0.1:5000           │
│  │     └── *.domain.com → proxy $upstream (per-service) │
│  └── Gunicorn/Flask (127.0.0.1:5000, --workers=1) [root]│
│                                                          │
│  Volumes:                                                │
│    /etc/nginx/conf.d/    ← Docker named volume          │
│    /etc/nginx/certs/     ← bind mount (pre-provisioned) │
│    /etc/nginx/conf.base/ ← baked into image (read-only) │
└──────────────────────────────────────────────────────────┘

Docker network: app_network (shared by anginX + all upstream apps)
Docker DNS: container_name → container IP (resolved at request time)
```

## Authentication Model

Single API key via `ANGINX_API_KEY` environment variable.

- ~~`POST /new/<key>`: key in URL path.~~ **RESOLVED:** now `POST /new` with
  `Authorization: Bearer <key>` — key no longer in `$uri`, so it's out of access.log.
- `DELETE /services/<domain>?key=<key>`: key as query param. Not logged (the `$uri` log
  format excludes query strings), so no leak.
- `GET /services`: **public**, no auth. Service registry (domain + port + name) is not sensitive.
- `GET /dashboard?key=<key>`: key as query param.
- `GET /health`: public, no auth.

## SSL Certificate Strategy

Two modes, selectable via `ANGINX_SSL_MODE` env var:

**`ANGINX_SSL_MODE=baked` (default):**
- `_ssl_<domain>.conf` files baked into the image at `/etc/nginx/conf.base/`
- Adding a new root domain requires image rebuild
- Simple and deterministic for a known set of domains

**`ANGINX_SSL_MODE=dynamic`:**
- Entrypoint scans `/etc/nginx/certs/` for `<domain>/fullchain.pem` directories
- Auto-generates `_ssl_<slug>.conf` include files in `/etc/nginx/conf.d/` (the named volume, not conf.base/)
- Reserved filename prefix `_ssl_` — the service list parser skips these files when scanning conf.d/ for `# anginx:` headers
- Add a new domain by adding its cert folder + restarting the container (no rebuild)
- If a cert directory is malformed, startup fails with a clear error message
- Generated service confs in dynamic mode include from `conf.d/`: `include /etc/nginx/conf.d/_ssl_<slug>.conf;`

Both modes: wildcard certs (`*.domain.com`) cover all subdomains per root domain.
Auto-SSL (Let's Encrypt certbot) is **deferred** — see TODOS.md.

## Volume/Base-Config Separation

`/etc/nginx/conf.d/` is a Docker named volume for persistence of generated configs.
Shared include files (`_proxy.conf`, `_ssl_*.conf`) live in `/etc/nginx/conf.base/`
(baked into image or generated at startup — never in the named volume).

`nginx.conf` includes only the generated per-service confs:
```nginx
include /etc/nginx/conf.d/*.conf;
```

`conf.base/` fragment files (`_proxy.conf`, `_ssl_*.conf`) are included directly
by each generated server block via `include /etc/nginx/conf.base/_ssl_<slug>.conf;`
and `include /etc/nginx/conf.base/_proxy.conf;`. They are NOT glob-included at the
http level — including `_ssl_*.conf` at http level would make the last-loaded cert
the default for all server blocks, breaking wildcard cert selection.

**API routing and HTTP→HTTPS redirect** are embedded directly in nginx.conf (not in
conf.base/, not in conf.d/). The port 80 `default_server` block doubles as both API
router and redirect:

```nginx
server {
    listen 80 default_server;

    location /new/    { proxy_pass http://127.0.0.1:5000; }
    location /services { proxy_pass http://127.0.0.1:5000; }
    location /dashboard { proxy_pass http://127.0.0.1:5000; }
    location /health  { proxy_pass http://127.0.0.1:5000; }

    location / {
        return 301 https://$host$request_uri;
    }
}
```

API endpoints are accessed via HTTP on port 80 within the shared Docker network
(e.g., `http://anginx/new/<key>` from another container). No SSL needed for
control-plane traffic — the API key provides auth. Gunicorn (127.0.0.1:5000) is
only reachable from within the anginX container; external access always goes through
this nginx block.

No file copying required. No entrypoint sidecar. Clean separation.

## Generated Config Structure

The API generates configs in this form:

```
/etc/nginx/conf.base/    ← baked into image (or generated by entrypoint)
  _proxy.conf            # shared headers, timeouts, hide headers
  _ssl_1com.conf         # cert paths for 1.com
  _ssl_2com.conf         # cert paths for 2.com

/etc/nginx/conf.d/       ← Docker named volume (API writes here)
  <app_name>.<domain>.conf   # one file per registered service
```

Template for a generated per-service conf (uses nginx variables for Docker DNS).
SSL include path is mode-dependent — Flask reads `ANGINX_SSL_MODE` at registration time:

```nginx
# anginx: domain=<domain> port=<port> name=<name> registered_at=<iso8601>
server {
    listen 443 ssl;
    server_name <domain>;
    # baked mode:    include /etc/nginx/conf.base/_ssl_<root_domain_slug>.conf;
    # dynamic mode:  include /etc/nginx/conf.d/_ssl_<root_domain_slug>.conf;
    include /etc/nginx/conf.base/_proxy.conf;
    resolver 127.0.0.11 valid=10s;
    location / {
        set $upstream http://<name>:<port>;
        proxy_pass $upstream;
    }
}
```

**Why `resolver + $upstream`:** Static `proxy_pass http://name:port;` causes nginx to
DNS-resolve the hostname at `nginx -t` time and at reload time. If the upstream container
is down, `nginx -t` fails — locking the API (no registrations or deregistrations possible).
Using a nginx variable defers resolution to request time. nginx -t never checks upstream
reachability. Docker DNS (127.0.0.11) is always available inside Docker networks.

**State persistence (source of truth):** The `# anginx:` comment header in each conf
file is the crash-recovery source of truth. Flask maintains an **in-memory registry
dict** (keyed by domain) that is the live authoritative state for the running process.
On startup: scan `/etc/nginx/conf.d/`, parse `# anginx:` headers (skip files with
`_ssl_` prefix — those are dynamic SSL fragments, not services), rebuild the dict.
On POST/DELETE: update the dict in the same request that writes/removes the conf file.
GET /services reads from the in-memory dict (O(1), no disk reads). Gunicorn's
`--workers=1` guarantees no concurrent mutation of the dict.
No sidecar registry.json — no two-phase commit, no drift risk.

**Root domain extraction:** last two dot-separated labels (e.g., `app.sub.1.com` → `1com`).
Only standard two-label TLDs supported in v1 (co.uk-style TLDs out of scope — see TODOS).
Registering a domain with no matching `_ssl_*.conf` returns 400 ("unknown root domain").

**name validation:** `^[a-z0-9][a-z0-9_-]{0,62}$` — Docker container name. Used as Docker DNS hostname in `proxy_pass` AND as conf filename prefix. Lowercase, no dots, no spaces.
**domain validation:** strict FQDN regex `^[a-z0-9]([a-z0-9.-]{0,61}[a-z0-9])?$` + structure check.
**port validation:** integer 1–65535.

## API Contract

### POST /new/<key>
**Request:**
```
Content-Type: application/json
{"domain": "app.1.com", "port": 7705, "name": "myapp"}
```
`name` is the Docker container name: used for Docker DNS resolution in `proxy_pass` AND
as the conf filename prefix. Single field, no mismatch possible.

**Behavior:** Idempotent — if domain is already registered, overwrites conf, validates, reloads.
**Success (200):**
```json
{"domain": "app.1.com", "name": "myapp", "port": 7705,
 "conf_file": "myapp.app.1.com.conf", "registered_at": "2026-05-22T15:00:00Z"}
```
**Errors:**
- 400: validation failed (body + nginx -t error if applicable)
- 401: invalid API key
- 429: max services cap reached (configurable via ANGINX_MAX_SERVICES, default 100)
- 500: conf.d not writable ("check volume mount"), nginx reload failed

### GET /services
**Response (200, always):**
```json
[{"domain": "app.1.com", "port": 7705, "name": "myapp",
  "conf_file": "myapp.app.1.com.conf", "registered_at": "2026-05-22T15:00:00Z"}]
```
Empty state: `200 []`

### DELETE /services/<domain>?key=<key>
**Behavior:**
1. Read conf file content to memory (for rollback)
2. Delete conf file from `/etc/nginx/conf.d/`
3. Run `nginx -t` on remaining configs
4. If nginx -t fails (should not happen): restore conf from memory → 500
5. If nginx -t passes: `nginx -s reload` → 200

**Success (200):** `{"domain": "app.1.com", "removed": true}`
**Errors:** 401 (bad key), 404 (not registered), 500 (conf.d error)
Note: Certs are NOT deleted on deregistration.

### GET /health
**Response (200):** `{"status": "ok", "nginx": "running", "services": N}`
**Response (503):** `{"status": "degraded", "nginx": "not running"}` (checks `/run/nginx.pid`)
Dockerfile: `HEALTHCHECK --interval=30s --timeout=5s CMD curl -f http://localhost:5000/health`

### GET /dashboard?key=<key>
HTML table of registered services: Domain (clickable link) | Container | Port | Registered.
Empty state: "No services registered. POST /new/<key> to add one."
401 if key missing or wrong.

## Input Validation & Security

All string inputs validated with strict regex **before** Jinja2 template rendering.
This closes the nginx config injection class (user-crafted nginx directives in domain/name fields).

```python
DOMAIN_RE  = re.compile(r'^[a-z0-9]([a-z0-9.-]{0,61}[a-z0-9])?$')
NAME_RE    = re.compile(r'^[a-z0-9][a-z0-9_-]{0,62}$')
PORT_RANGE = range(1, 65536)

def validate_domain(domain: str) -> None:
    if not DOMAIN_RE.match(domain):
        raise ValidationError("invalid domain characters or length")
    if len(domain.split('.')) < 2:
        raise ValidationError("domain must be a fully qualified domain name (e.g. app.1.com)")
```

Reject any input failing validation with 400 before any file write.

## Error Handling

All subprocess calls wrapped with:
```python
except subprocess.TimeoutExpired: → 500 "nginx -t timed out"
except subprocess.CalledProcessError: → 400/500 + stderr
except PermissionError: → 500 "conf.d not writable — check volume mount"
except OSError as e:
    if e.errno == errno.ENOSPC: → 500 "disk full"
    else: → 500 str(e)
except json.JSONDecodeError: → not applicable (no sidecar JSON)
```

## Reload Mechanism

1. Write conf.tmp → `os.rename()` to conf (atomic, POSIX)
2. `nginx -t` (subprocess, 5s timeout): FAIL → rollback rename, return 400
3. `nginx -s reload` (sends SIGHUP to nginx master; returns immediately)
4. Return 200

Note: Requires `pid /run/nginx.pid;` in nginx.conf (standard in official nginx image).

## Accepted Scope (v1 deliverables)

- **Docker image**: nginx + Gunicorn (--workers=1) via supervisord; ports 80 (redirect), 443
- **Startup**: poll `/run/nginx.pid` before accepting connections
- **SSL modes**: `ANGINX_SSL_MODE=baked` (default, `_ssl_*.conf` baked into image in conf.base/) or `dynamic` (scan certs at startup, write `_ssl_*.conf` to conf.d/ with reserved prefix); service conf include path is mode-dependent
- **nginx.conf**: includes `conf.d/*.conf` only (not conf.base glob); `pid /run/nginx.pid;`; port 80 default_server block handles API routing to 127.0.0.1:5000 + HTTP→HTTPS redirect for all other paths; no SSL cert fragments at http level
- **Generated conf template**: uses `resolver 127.0.0.11 valid=10s` + `set $upstream`
- **State persistence**: `# anginx:` comment headers in conf files; parsed on startup
- **POST /new/<key>**: idempotent (overwrites on duplicate); full validation; max services cap
- **GET /services**: public; 200 []; sourced from conf file header parsing
- **DELETE /services/<domain>**: removes conf, rollback on failure; no cert deletion
- **GET /health**: checks nginx PID; 200/503; Docker HEALTHCHECK
- **GET /dashboard?key=<key>**: Jinja2 table; clickable domain links; empty state message
- **Input validation**: FQDN regex, container name regex, port range; rejects before template render
- **Error rescue**: PermissionError, OSError, disk full → actionable 500 messages
- **ANGINX_MAX_SERVICES**: env var, default 100; 429 when exceeded
- **Python client (anginx-client)**: `register()`, `deregister()`, `AnginxError`; 3-retry with backoff
- **docker-compose.yml example**: app_network, volume mounts, env vars
- **README**: nginx-as-SPOF warning; 502 upstream caveat; URL key logging tradeoff; network requirement

## Test Plan

Two-layer strategy: fast unit tests for logic, Docker-compose integration tests for the real reload path.

**Unit tests** (`tests/unit/`, pytest, mocked subprocess, target <5s):
- `test_validation.py`: `validate_domain` (rejects single-label, bare hostnames, injection attempts; accepts valid FQDNs); `validate_name` (valid Docker names, invalid chars); `validate_port` (boundary: 1, 65535, 0, 65536)
- `test_parser.py`: `# anginx:` header parsing — well-formed header, missing header (file skipped), `_ssl_*` prefix file (skipped), malformed field (skipped with warning), all fields extracted correctly
- `test_root_domain.py`: `app.1.com` → `1com`, `sub.app.2.com` → `2com`, `app.co.uk` → `couk` (best-effort, PSL deferred)
- `test_registry.py`: POST updates in-memory dict, DELETE removes from dict, GET reads from dict, overwrite on duplicate domain

**Integration tests** (`tests/integration/`, Docker Compose with real anginX image, target <60s):
- Register a service → nginx reloads → GET /services shows it → GET /health shows services=1
- Register same domain again → idempotent overwrite → still 1 service in GET /services
- DELETE /services/<domain> → conf removed → nginx reloads → GET /services empty
- GET /health → 200 with `nginx: running` when nginx master is up
- 101st registration → 429 (ANGINX_MAX_SERVICES=100 default)
- Bad API key → 401 on POST, DELETE, dashboard
- nginx -t failure simulation: manually corrupt a conf file in conf.d/ → GET /health shows nginx degraded

**CI**: GitHub Actions with `docker/build-push-action`. Integration tests run `docker compose up --build` then hit the container via `http://localhost:80`. Test matrix: `ANGINX_SSL_MODE=baked` and `ANGINX_SSL_MODE=dynamic` (with self-signed test certs baked into the test compose).

## Outside Voice Findings (agy eng review pass)

Two issues surfaced from an independent implementation pass against this design:

**1. Startup initialization must not run at module import time.**
`initialize_dynamic_ssl()` and `rebuild_registry()` cannot be top-level module code. Unit tests
import the Flask app module — if those functions run on import, they immediately try to access
`/etc/nginx/conf.d/` and fail. Fix: use an **app factory pattern** (`create_app()` function)
and call startup init inside `with app.app_context()`. Tests call `create_app()` with a test
config that overrides `CONF_D` to a temp directory. All existing unit test plans already assume
this; make it explicit in the implementation.

**2. nginx access log key masking must be specified.**
The design says "mask API key in log format" but never defines the format string. Without it,
implementers skip it or get it wrong. The nginx log format to use:
```nginx
log_format anginx '$remote_addr - $request_time [$time_local] '
                  '"$request_method $uri $server_protocol" $status $body_bytes_sent';
```
Use `$uri` (not `$request_uri`) — `$uri` strips the query string, which eliminates `?key=`
leakage. The registration key now travels in the `Authorization: Bearer` header (not the
path), so nothing secret reaches `$uri`. Log format named `anginx` is applied in the
port 80 server block: `access_log /var/log/nginx/access.log anginx;`
